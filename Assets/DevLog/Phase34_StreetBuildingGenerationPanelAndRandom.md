## 3. 最终开发功能

### 3.1 可维护的 HDA 原生消费链

**状态：已完成；证据：[已验证：独立加载的最终 HDA 结构与合约源码]。**

本轮从磁盘 HDA 新建锁定实例，确认 `StreetBuildingCore` 为 49 个直接子节点、9 个 Network Box、9 个 Sticky Note。主要生成算法仍保持专职节点，普通筛选与属性清理移入可直接查看和编辑的原生 SOP：

| 分支 | 最终原生处理 |
|---|---|
| 正面／次正面 | `FRONT_TARGET_FILTER`、`FRONT_POINTS_ONLY` 使用 Blast；`FRONT_INSTANCE_ATTRIBUTES` 使用 Attribute Delete |
| 侧面／后面 | `SIDE_REAR_TARGET_FILTER`、`SIDE_REAR_POINTS_ONLY` 使用 Blast；`SIDE_REAR_INSTANCE_ATTRIBUTES` 使用 Attribute Delete |
| 正式实例过滤 | `REAL_INSTANCE_FILTER` 剔除缺件预览点；`REAL_INSTANCE_ATTRIBUTES` 清理预览属性 |

轻量语义节点继续标记输出角色，正式缺件数量由过滤前后点数差获得。附件校验按 Detail 扫描，保留空输入边界，避免按每个点重复扫描整个集合。

中文注释与九个阶段导航说明输入、输出、修改入口、属性查看方式和扩展边界。输出编号保持稳定：0 主模型、3 附件、5 metadata、6 缺件预览；1、2、4 仍是兼容空槽，不能按名称当作已交付 LOD 或碰撞系统。

`validate_streetbuilding_maintenance.py` 为原生链提供拓扑、属性定义／精度／值、分组的零容差比较，以及维护失败恢复测试。它是验收工具，不是要求每次开发重新执行的重建流程。

### 3.2 门素材权重与可行铺排

**状态：已完成；证据：[已验证：最终 HDA 标记与独立合约源码]；本轮行为结果见第 6 节。**

门的可行性判断与素材选择权重分开处理：

- 先识别能够完成门、橱窗和墙体铺排的候选与位置，再按素材权重选择，不让一种门拥有较多可放置位置就额外放大其素材概率。
- 门位选择考虑剩余连续格能否由当前墙体／橱窗跨度完整铺满，避免选到一个局部合法、整体却产生空洞或强制压缩的门位。
- 不可行的高权重候选不能压过实际可行的低权重候选；同跨度素材共享可行性求解，减少重复工作。
- 商业门按整栋首层、物理立面分配；L 形同方向分段不重复获得门额度，关闭的后立面不参与。
- 优先尝试满足请求的完整组合；真实容量不足时报告请求、实际与原因，不改写用户请求。精确门请求无解时明确失败，不伪装成成功。
- 同上下文重复 Cook 应确定，素材目录排序变化不应改变门的选择结果；非正权重在目录校验阶段拒绝。

门数、橱窗数和比例继续来自实例参数；StyleConfig 只提供素材权重、跨度、尺寸与适用范围。

### 3.3 自有生成面板：编辑与生成分离

**状态：已完成；证据：[已验证：最终 C# 源码]；Unity 操作链路待复验。**

`StreetBuildingAuthoringEditor` 接入 `StreetBuildingParameterPanel`，按建筑体块、首层门窗、标准层门窗、屋顶与线脚、附件、局部覆盖、种子与调试组织参数。

参数修改使用事务写回 HDA 实例与 HEU 参数缓存／preset；常规修改关闭自动参数 Cook 与 Session Sync AutoCook，用户主动点击“生成”才提交本次生成请求。生成请求中／执行中禁止重复提交。

数字生成参数采用 MinMaxSlider：

- 两端相等为固定值，不相等为随机范围；整数参数端点取整。
- 建筑宽深在自有面板按格数显示，按 StyleConfig 的格宽换算回 HDA 原有米制字段；外部地块输入时尺寸由输入地块决定，不用独栋范围覆盖。
- 枚举／开关采用候选选择：单候选固定，多候选在生成时选择一个；至少保留一个候选。
- 橱窗立面候选生成时选取非空子集；V2 会先与实际启用立面求交。
- 商业门注明“整栋首层”，标准层窗注明“每层每物理立面”，橱窗注明“每个选中启用立面”。单双宽窗均计一个模块。
- 种子、调试开关与覆盖楼层范围等技术／作用域字段按直接控件编辑，不把所有数字都当作生成范围。

区间和候选 JSON 保存在 HDA 实例隐藏字段 `unity_generation_policy`，生成审计序号为 `generation_sequence`。初始配置从当前实例字段读取，不从 StyleConfig 导入生成默认值，也不在 Authoring 组件保存第二份生成配置。

### 3.4 成功结果快照、修改摘要与版本状态

**状态：已完成；证据：[已验证：最终 C# 源码]。**

`StreetBuildingPanelState` 分开保存当前输入、已提交输入、上次成功结果；输入哈希用于判断“参数已修改”还是“结果已更新”。状态还区分生成中、失败、实例未载入、会话不可用和恢复后待验证。

- Authoring 保存成功结果与验证审计，供重开后显示；这些快照只用于比较与展示，不回填生成参数。
- 成功提交要求读取有效 metadata、规则版本与墙段映射，并检查生成对象／网格引用，不能只凭 Cook success 标记为最新。
- Cook 期间从原生 Inspector 产生的后续编辑单独记录，生成完成后恢复；它们不会被混入已经提交的结果版本。
- 会话或 HAPI 节点身份变化后，旧成功记录标为待验证；恢复连接不等于已经重新生成。
- `StreetBuildingChangeSummary` 显示改前／改后、影响范围、来源及当前模式不使用的字段。体块变更后旧墙段图只代表上次结果，摘要明确标注预计范围。
- V2 输入哈希还包含素材依赖内容与 HDA 依赖哈希；仅保持 Prefab 引用不变不足以认定结果仍有效。

性能上仅对选中楼栋以约 0.35 秒间隔观察，Cook 中读取缓存，不逐次重绘扫描几何。完整素材检查改为显式按钮，减少 Inspector 重绘中的重复校验。

### 3.5 立面示意图与局部覆盖联动

**状态：已完成；证据：[已验证：源码与独立 HDA 墙段合约]。**

HDA 输出 `panel_facade_segments`，Unity 根据真实墙段生成俯视示意图，而不是用固定矩形代替所有体块。

- 记录物理立面 ID、覆盖目标、墙段角色、端点与格数；矩形为 4 条墙段，四个方向的 L 形为 6 条。
- 显示采用正面朝下、左右为建筑自身方向；绘制与点击命中使用相同坐标映射。
- 正面、次正面、侧面（左／右）、背面是覆盖作用域；物理立面 ID 另用于标示同方向分段共享额度，两者不混为一谈。
- 图上选墙段与覆盖列表选择联动；显示楼层／数量／排列摘要，缺失目标或不合法楼层范围给出提示并保留请求。
- 删除中间覆盖行时同步移动对应区间规则索引，避免新旧行索引错配。

拓扑已经修改但尚未成功生成时，图与诊断仍按上次成功结果标注，不声称已经反映新输入。

### 3.6 有效字段隔离与附件诊断

**状态：已完成；证据：[已验证：最终源码与独立 active-fields 合约]。**

最终规则版本为 `active_fields_v2`。隐藏或当前模式不用的字段可以保留原值，但不应参与当前覆盖是否生效的判定：

- 数量固定、范围、比例按当前模式解释，不能由隐藏最大值触发额外生成。
- 住宅用途不激活商业橱窗覆盖；只覆盖首层的行不使用标准层字段，反之亦然。
- 后面的无效／未激活覆盖行不能遮蔽前面的显式有效覆盖。
- 自动继承模式的有效数量与排列仍遵循实际规则，不简单把“模式为自动”理解成忽略全部显式输入。
- 同一有效字段规则覆盖实例局部覆盖与外部地块输入解析。

`StreetBuildingAttachmentDiagnostics` 将五类附件 × 三个楼层组的 15 行记录解释为请求上限、生效上限、挂点数、素材适用性、随机命中、实际数量与来源。关闭、零概率、无素材、无合格挂点、预算截断等分别显示，数据损坏／缺行不被当作零输出。

### 3.7 参数事务、断线恢复与失败保全

**状态：已完成；证据：[已验证：最终 C# 源码]；故障交互与重开仍待本轮复验。**

- `StreetBuildingParameterTransaction` 保全原生 preset、参数缓存与对象引用，先同步原生 Inspector 尚未提交的输入，再执行一次 Undo 事务；结构变更后以 HAPI 新索引刷新缓存。
- 事务异常恢复原生参数与缓存，报告无法同步的具体原因；缺口单位在批量恢复末尾显式恢复，避免格数字段回调覆盖原单位。
- `StreetBuildingSessionRecovery` 仅在显式“恢复实例连接”时创建 HAPI 实例，从 preset 与未生成的缓存编辑恢复，不在 Inspector 重绘中自动建节点或用素材默认值初始化。
- `StreetBuildingOutputRetention` 在 Cook 前保全实际 HEU 输出层级、运行时网格／材质与引用；失败时优先保留仍完整的原对象，必要时恢复备份与输出绑定。
- 保全只针对 HEU 生成输出，不清理人工场景对象；只有实际恢复与引用检查成功才显示“保留上次结果”，否则明确显示未能确认保留。
- Style Apply 的失败处理不依赖再次成功 Cook 才恢复输出；即使原生会话不可写，也继续尝试保全结果与用户请求缓存。

项目侧恢复实现使用 HEU 的现有接口及部分反射访问，未修改 HoudiniEngineUnity 插件文件。反射依赖插件内部结构，插件升级后必须专项回归。

### 3.8 分组随机 V2：独立身份、重抽与复现

**状态：已完成；证据：[已验证：源码、最终 HDA 接口与独立 random 合约]。**

最终 HDA 的 `random_algorithm` 默认仍是 1。已有实例保留原算法，V2 通过明确操作启用，不能写成全部场景已经自动迁移。

V2 上下文由算法版本、稳定实例身份、主种子、组序号和字段键组合；体块、首层、标准层、附件分别拥有序号。Unity C# 与 HDA VEX 使用配套稳定散列／随机序列，并有共享测试向量约束。

- 整数范围使用拒绝采样避免直接取模或浮点取整偏差；宽整数区间用两次采样组合，避免上界加一溢出。浮点范围检查端点有效性。
- “重抽体块／首层／标准层／附件”只推进所选组序号；“复现当前方案”不推进序号。依赖仍然存在：体块改变会使门窗与附件重新求解，独立随机流不表示几何完全无关联。
- “按请求抽样”与“可行组合优先”是显式策略；后者按依赖条件筛选合法组合，不承诺对所有完整建筑组合全局等概率。
- 宽深在 V2 按整数格采样，先处理体块／尺寸依赖；L 形缺口按可行范围约束本次采用值，原请求端点保留在 policy。整体无解或固定值冲突明确失败。
- 外部地块不由独栋尺寸随机范围覆盖；稳定 `building_id` 进入外部建筑随机上下文。
- 普通 Recook／重载不自动推进分组序号；旧兼容字段不重新获得“每次 Cook 偷偷重抽”的语义。
- “复制为独立建筑”要求当前结果已成功验证，复制保留配置与当前外观，为副本创建新随机身份并标记待验证；新身份在下一次主动生成生效。
- V2 Bake 增加结果新鲜度检查：生成中、未验证或输入哈希不匹配时拒绝 Bake，不能把旧外观作为新参数的验证结果发布。

### 3.9 混合跨度下的精确左右对称

**状态：已完成；证据：[已验证：最终 HDA 与本轮 26 项独立合约]。**

标准层“左右对称”不仅对格位置做镜像，还匹配成对模块的跨度、角色与素材引用，验证中心位置和连续覆盖。奇数数量处理中心模块，L 形继续按每层每物理立面共享窗额度。

可实现精确配对时写入 `symmetry=paired_exact`；素材跨度／数量奇偶导致严格对称无解时保留用户数量，报告 `symmetry=unavailable_preserved_quantity`，不为了视觉对称偷增减窗数。

该合约覆盖算法 1／2、单双宽混合、不同奇偶数量与四个方向 L 形；切回非对称排列应恢复对应确定性结果。

## 7. 性能、兼容性与扩展点

### 7.1 CPU 与 GPU 分工

| 阶段 | 成本与控制 |
|---|---|
| Houdini 编辑期 | 可行铺排与随机在 Cook 中运行；同跨度复用求解，普通过滤交给原生 SOP；无本轮完整 Cook 性能基准 |
| Unity 编辑期 | 显式生成、选中对象节流观察；失败保全会复制输出及非持久网格／材质，有额外内存峰值，不是零成本功能 |
| 发布运行时 | 只消费 Bake 数据，不执行 HAPI 参数采样、Houdini Cook 或面板事务 |
| GPU 渲染 | 沿用已有 Mesh／Prefab／材质路径；本阶段未新增 GPU 剔除、Indirect Draw 或 LOD 系统 |

### 7.2 移动端与 Shader 风险

本阶段没有新增 Shader、RendererFeature 或 RenderPass，不增加项目自定义 keyword、全屏 Blit、MRT 或中间 RT。沿用材质的 Instancing 选项不等于实际合批，URP 既有变体仍需构建裁剪与实测，不能据此承诺总变体低于 200。

面板允许的规模／密度增长可能增加 Bake 后实例数、DrawCall、SetPass 和阴影成本。后续应基于真实楼群验证 Chunk／批处理／LOD，不以编辑期生成成功替代 Mali、Adreno、Apple GPU 性能验收。

### 7.3 扩展边界

- 新随机字段先明确所属组、整数／连续／候选语义及依赖，再接入稳定键和累计合约。
- 新覆盖字段必须定义当前模式有效性及数量单位，不让隐藏旧值改变当前生成。
- 新素材仍只进入 StyleConfig 的候选／约束，不承担数量、排列或生成开关。
- 新状态或诊断应延续当前成功结果版本机制，不能仅增加“成功”提示而绕过 metadata 与输出引用验证。
- HEU 反射恢复、Pipeline 命令适配分别独立维护，避免扩展为侵入第三方插件的通用框架。
